## المشكلة والحل

يحتاج الباحث في المعرفة الإسلامية إلى جواب يحفظ النص والمعنى، ويُظهر أصل القول وحدود الاستدلال. قد يبدو الجواب مقنعًا بينما يخطئ في الاقتباس، أو يستند إلى مرجع لا يسند عبارته، أو يجزم في حالة تحتاج إلى استيضاح.

بنينا رحلة تجعل **السؤال والجواب والدليل في موضع واحد**: شخصيات باختصاصات واضحة، أدوات للنصوص والشواهد والحساب، بث للإجابة أثناء إعدادها، ومراجع يمكن فتحها ومراجعتها. يظل الاستيضاح والامتناع المبرر والإحالة إلى المختص نتائج مناسبة حين لا تكفي المعطيات.

## اختر رفيق السؤال

| الشخصية | ما تقدّمه في المجلس | بداية مناسبة |
|---|---|---|
| **برق الفتى** | القرآن والحديث واللغة والشواهد وأدوات المعرفة والحساب | «لماذا يعبد المسلمون الكعبة؟» ثم افتح مرجع الجواب |
| **لينة** | شرح الأحكام الفقهية وشروطها وأوجه الخلاف، مع الاستيضاح عند الحاجة | سؤال فقهي محدد، ثم متابعة عن شروط الحكم ومصدره |
| **قبس** | البحث والمقارنة وربط الأدلة في الأسئلة المركبة | «ما المقصود بتوحيد الألوهية؟» ثم راجع المصادر والعبارات المنسوبة إليها |

برق الفتى نموذج عربي تطوّره سلسبيل وتملك أوزانه؛ لا نعمّم هذا الوصف على النماذج التي تستعين بها لينة وقبس. الشخصيات مساعدات معرفية، وليست جهات إفتاء.

## ما يميّز العمل

| الإضافة | القيمة للمستفيد | دليل المراجعة |
|---|---|---|
| **الذاكرة النصية المهيكلة NMN** | فصل النص وهويته وموضعه عن الشرح، والرجوع إلى الأصل عند الاستشهاد | [الابتكار وطلب الحماية المرتبط به](docs/INNOVATION_AR.md) |
| **التجاور القرآني** | مقارنة قرائن استعمال الألفاظ والجذور، مع تمييز المؤشر الإحصائي عن التفسير | [البحث وحدود المثال](docs/INNOVATION_AR.md) |
| **من العدد إلى الشاهد** | فحص موضع النص بأدوات الاشتقاق والقرآن والحديث، إلى جانب أدوات حسابية تعليمية | [أدلة القدرات المؤرخة](evidence/README.md) |
| **مجلس بثلاث شخصيات** | اختيار الاختصاص، بث الجواب، فتح المصادر، والعودة إلى سياق كل شخصية | [رحلة الاستخدام الحالية](docs/USER_GUIDE_AR.md) |
| **RAG وتخصيص النية** | أدلة مؤرخة على التضمين والفهرسة وعينات SFT الخاصة بالمهمة | [بطاقة RAG](data-cards/rag/README.md) · [بطاقة SFT](data-cards/sft/README.md) |

تضم الشرائح ٨ و٩ و١١ لقطات حديثة من المجلس: [استكمال الآية](evidence/screenshots/council-nmn-current.png)، و[التجاور الإحصائي](evidence/screenshots/council-adjacency-current.png)، و[جدول الفرائض](evidence/screenshots/council-inheritance-table.png). جُرّب كل مثال مرة واحدة؛ بقي خطأ في الوزن الصرفي لـ«النفس» خارج قسم البصمة، فلا تثبت هذه اللقطة صحة التحليل اللغوي الكامل.

[مصفوفة إثبات الابتكار](evidence/INNOVATION_EVIDENCE_AR.md) تربط كل إضافة ببديل محدد ودليل ظاهر. تشمل أربع مقارنات تاريخية كاملة بين الشخصيات، بما فيها المقارنة غير الناجحة، وتجربة حالية لفتح ٣ شواهد «رشيد» وشاهد «مرشد». يستطيع المحكّم [إعادة حساب الملفات وإعادة تجربة القدرات](evidence/REPLAY_GUIDE_AR.md) بخطوات معلنة.

تشمل [خريطة المصادر والحقوق](docs/SOURCES_AR.md) المراجع المعتمدة في التحدي، والمصادر التي تظهر في الأدلة، وإضافة **[مِقْرأ للدكتور أيمن فاتح العامر](https://miqrawajiz.netlify.app/)**. نميّز المرجع المضاف من المحتوى المثبت استيعابه وفهرسته.

## للمحكّم: ابدأ بخمس دقائق

1. افتح المجلس، واختر الفتى، واسأل «لماذا يعبد المسلمون الكعبة؟» ثم افتح المصدر وراجع تصحيح فرضية السؤال.
2. اختر لينة أو قبس، وأرسل سؤالًا محددًا؛ انتظر الرد النهائي وافتح «مصادر الإجابة».
3. عد إلى الفتى للتحقق من بقاء محادثته. عند ظهور زر إحالة، جرّب إرسال السؤال إلى الشخصية المقترحة.
4. راجع [الابتكارات وأدلتها المقارنة](evidence/INNOVATION_EVIDENCE_AR.md)، ثم [المعمارية](architecture/README.md) و[المصادر وتغطية RAG](docs/SOURCES_AR.md).
5. اتبع [ورقة إعادة الفحص](evidence/REPLAY_GUIDE_AR.md)، مع فصل النتائج الحالية عن [التقييم التاريخي لـ٥٠ سؤالًا](evaluation/README.md) و[أصول المشروع السابقة](challenge/README.md).

## النسخة الحالية وما تثبته الأدلة

أصبح المجلس النسخة الأساسية في **٦ أكتوبر الساعة ١٧:٥٥:٣٩ بتوقيت الرياض**. يثبت إيصال التسليم نجاح ٣٦٨ اختبارًا محليًا للحزمة، و٦٠ فحص تشغيل محليًا، و٢٨ فحصًا عامًا، مع تجربة بث ومراجع للشخصيات الثلاث. هذه نتائج تشغيل وعينات محددة، وليست نسبة دقة لجميع الإجابات. بقيت ملاحظة في اتساع بعض عبارات قبس ودقة إسنادها؛ تُعرض في [حدود النسخة](docs/LIMITATIONS_AR.md).

## الكود والتشغيل المحلي

سلسبيل مزوّد خدمة API مستقل. يسلّم المستودع كود التطبيق والأدلة المختارة للمشاركة؛ الأوزان ومصنع النماذج وقواعد المعرفة الخاصة الكاملة خارج نطاقه.

**نطاق الكود:** مجلد `council/` يضم أصول واجهة المجلس العامة، ووحدتي الطابور وتصنيف أخطاء المزوّد من التطبيق، وبيان أصلها، ومعاينة محلية للواجهة، ووصف عقد الاتصال بالخادم المستضاف. اجتاز ٢٤ اختبارًا: ٥ للتصدير والمعاينة، و٦ للطابور، و١٣ لتصنيف الأخطاء. هذه المعاينة لا تشغّل خادم الشخصيات الثلاث محليًا. يبقى `app/` مثالًا مستقلًا للمطور على استخدام API برق الفتى. التجربة العامة للمجلس لا تطلب من المستخدم إدخال مفتاح، وواجهتا لينة وقبس لعموم المطورين لم تُعلنا متاحتين بعد. [تفاصيل الكود وحدوده](docs/COUNCIL_SOURCE_AR.md).

يلزم Node.js 22 أو أحدث. الاختبارات لا تحتاج مفتاحًا، والإجابات الحية تحتاج حسابًا ومفتاحًا مخوّلًا لدى سلسبيل:

```sh
cd app
npm ci
```

انسخ `.env.example` إلى `.env`، واضبط `SALSABEEL_API_KEY`، ثم:

```sh
npm start
```

افتح `http://127.0.0.1:8791`. [الحصول على المفتاح والإعداد](docs/SETUP_AR.md) · [بوابة المطورين](https://barq.salsabeel.ai/developers/?lang=ar).

```sh
npm test
npm run check
```
