# التقييم: التشغيل لا يساوي صحة الجواب

تحتوي [المقارنة](mission50-comparison.json) على **كل الأسئلة الخمسين** في مجموعتي قبل/بعد، دون حذف الحالات غير الناجحة. تُنشر حالة الطلب وزمنه وطول الجواب وبصمته ومرجعه المعلن، دون نصوص المصادر الطويلة أو بيانات التشغيل الخاصة.

- قبل: سجل ٣ أكتوبر ٢٠٢٦.
- بعد: السجل التاريخي المسمّى `AFTER_P5_ON_20261005_0745.jsonl`؛ قد توجد تحديثات لاحقة على الخدمة.
- المجموعة معروفة أثناء التطوير، وليست قياسًا أعمى للتعميم.
- [الملخص المحسوب](summary.json) يقيس HTTP وحضور الجواب والزمن فقط. لا يُقرأ كتحسن دقة.
- [الأسئلة](questions.json) أمثلة تطوير مصطنعة، وليست معلومات أشخاص حقيقيين.

## كيف يعيد المحكّم التجربة؟

افتح الموقع، انسخ سؤالًا، دوّن التاريخ والجواب والرابط، ثم قيّم المحاور التالية كلًا على حدة:

1. هل فهم السؤال وصحح فرضيته إن لزم؟
2. هل النص المنقول يطابق المصدر؟
3. هل المصدر يجيب عن السؤال ويمكن فتحه؟
4. هل الاستنتاج داخل حدود الدليل؟
5. هل امتنع أو أحال عندما يكون المطلوب فتوى شخصية أو حالة متخصصة؟

الإحالة المبررة نجاح في الحالة المناسبة؛ مهلة الخدمة أو خطأ الشبكة أو رفض سؤال معرفي داخل النطاق ليست امتناعًا صحيحًا. يحتاج الحكم الديني والدلالي إلى مراجعة مختص، ولا يغني عنه فحص HTTP.

يمكن إعادة تشغيل مجموعة الأسئلة بأداة [replay.mjs](../scripts/replay.mjs) على **نسختك المحلية** ذات المفتاح، بترتيب متسلسل. يحتفظ الناتج محليًا خارج Git. لا تقارن القياسات الزمنية دون توحيد الحمل والإصدار والعتاد؛ الخدمة المستضافة متغيرة.


المراجعة المستقلة تضيف قياسًا نوعيًا للحالات الفعلية: [سجلها](independent-review-20261005.json)، مع [بوابات قبول الإصلاح](ACCEPTANCE_AR.md). لا تدمج نتائجها مع مجموعة الخمسين في نسبة دقة واحدة.
